# v4 索引健康度工作台设计

## 背景

当前 AstrBot 页面仍使用旧版四项统计卡：已索引、待分类、重复和完成标签。它能反映目录数量，但不能回答“哪些图片真正满足 v4 索引契约”。之前的 v4 健康度视觉稿没有接入实际插件页面，因此重新安装后用户仍看到旧布局。

本次方案采用用户确认的方案 A：保留现有缩略图卡片和处置工具，在实际捕获/目录工作台顶部加入 v4 健康度面板，并同步 `pages/semantic/` 与 `pages/a_manage/semantic/` 两份页面副本。

## 目标

- 让当前“表情索引”工作台直接展示 v4 完整率和健康状态。
- 保留现有缩略图、分页、批量选择、选择索引、全量重索引和一键忽略功能。
- 让用户点击状态或标签气泡即可筛选对应资源。
- 通过版本升级和资源缓存版本，确保 AstrBot 不继续使用旧页面副本。
- 用后端汇总数据驱动状态，避免前端根据不完整的分页数据猜测全包统计。

## 非目标

- 不改变普通“表情包管理”页面的分类移动、上传和删除语义。
- 不重新设计缩略图卡片的图片预览和处置接口。
- 不把 v4 健康度统计写入 catalog；它是只读展示模型。

## 用户界面

### 健康度面板

面板位于资源包选择和操作工具之前，包含：

1. 左侧圆环：显示 `v4_complete / (v4_complete + needs_rebuild)` 的百分比；没有可检查条目时显示“未开始”。
2. 右侧四项统计：
   - `v4 完整`：版本、提示词、SHA、主分类和全部语义字段均通过检查。
   - `需重建`：已经进入目录但 v4 契约不完整或文件指纹不一致。
   - `待分类`：未索引且不是重复事件的待处理图片。
   - `重复待忽略`：重复捕获事件，保留现有图片但等待忽略/拉黑。
3. 状态说明：明确告诉用户完整率的分母只包含“已整理 + 需重建”，避免待处理图片让百分比产生歧义。
4. 四项状态均为可点击筛选入口；筛选只改变当前工作台的展示，不改变 catalog。

### 标签和分类气泡

沿用现有 `folders` 统计，使用圆角气泡展示标签与分类；点击气泡设置当前 `category` 过滤并重新加载工作区。选中态使用深绿色背景和白色文字，未选中态使用浅绿色边框。状态筛选和标签筛选可以组合，清除任一筛选时恢复全包数据。

### 视觉规范

- 背景使用现有浅薄荷绿，不引入新的大面积渐变。
- 数字使用统一的等宽数字样式、居中对齐和明确的权重，避免统计卡中的数字漂移。
- 环形进度只承担“整体健康度”这一项职责；细项数量通过右侧统计完成解释。
- 缩略图区域保持现有分页和卡片密度，避免为了健康度面板压缩图片预览。
- 保留键盘焦点、`aria-live` 状态播报和 `prefers-reduced-motion` 行为。

## 数据契约

`capture/workspace` 的 `summary` 新增 `v4` 对象：

```json
{
  "v4": {
    "complete": 45,
    "needs_rebuild": 3,
    "pending": 6,
    "duplicate": 2,
    "checked_total": 48,
    "completion_percent": 94,
    "status": "partial"
  }
}
```

统计规则：

- `complete` 使用现有 v4 当前条目判断逻辑，要求当前 SHA、索引版本、提示词版本、合法主分类和语义字段全部有效。
- `needs_rebuild` 是已进入 catalog 但不满足 v4 当前条目契约的唯一图片数。
- `pending` 与 `duplicate` 复用现有捕获工作台的去重结果，不能重复计算同一文件。
- `checked_total = complete + needs_rebuild`。
- `completion_percent = round(complete / checked_total * 100)`；`checked_total` 为零时返回 `null`，前端显示“未开始”。
- 后端必须从完整 catalog 和当前资源包状态计算汇总，不能只从当前分页返回值计算。

## 实现边界

- 后端：在 `mixins/capture_index_api.py` 的工作区构造中集中生成 v4 汇总；复用 `indexing.full_reindex_entry_is_current` 的契约判断，避免页面和重索引任务出现两套标准。
- 前端：在两份 `script.js` 的同一渲染流程中生成健康度 DOM；动态数据使用 `textContent`/DOM API，不把文件名、分类或模型文本拼入 `innerHTML`。
- 样式：在两份 `style.css` 增加健康度面板、环形进度、数字排版和状态气泡；移动端改为单列堆叠。
- 版本：`metadata.yaml`、README badge、`main.py @register` 和 CHANGELOG 统一升级到 v2.1.8；页面静态资源查询参数同步升级。
- 测试：增加后端 v4 汇总边界测试、双页面结构/运行时契约测试和版本一致性测试。

## 错误和空状态

- 没有 v4 检查条目：圆环显示“—”，说明显示“尚未开始 v4 检查”。
- 全部条目完整：显示“v4 索引完整”，仍允许刷新和查看缩略图。
- 存在需重建条目：显示“部分完整”，点击“需重建”只筛选，不自动启动重索引；用户继续通过现有“全量语义重索引”按钮确认操作。
- 后端汇总失败：保留缩略图区域的错误提示，健康度面板显示“状态暂不可用”，不阻塞删除、忽略等独立操作。

## 验收标准

- 打开实际“表情索引”入口即可看到 v4 健康度面板，而不是旧四项统计卡。
- 面板显示的数据与后端完整资源包统计一致，分页切换不会改变总数。
- 点击 v4 状态或标签气泡后，缩略图筛选结果和选中态正确更新。
- 两份页面副本的 HTML、CSS、JavaScript 契约一致。
- 版本和静态资源缓存版本均为 v2.1.8，重新安装/刷新后不会继续命中旧资源。
- 现有全量测试、页面契约测试、架构检查和 JavaScript 语法检查全部通过。
