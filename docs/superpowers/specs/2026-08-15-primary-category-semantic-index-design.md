# 表情包主分类与语义索引重构设计

## 目标

从当前“多个标签等权参与自动选图”改为“一个稳定主分类负责路由，少量辅助标签和语义描述负责理解”，降低视觉模型误加标签造成的自动发送误匹配，并作为 `v2.1.5` 发布。

## 已批准的主分类

自动发送只使用以下 12 个主分类：

`开心、悲伤、尴尬、无奈、疑惑、震惊、愤怒、吐槽、赞同、拒绝、卖萌、围观`

每张图片只能有一个 `primary_category`。旧的英文分类名通过已有别名归一化到这组中文主分类。

## 数据模型

主 catalog 条目新增或规范以下字段：

```json
{
  "primary_category": "尴尬",
  "semantic_tags": ["认错", "反问"],
  "semantic_summary": "角色因自己说错话而尴尬认错，带有轻微自嘲意味。",
  "visible_text": "但是不是你自己发的吗",
  "text_meaning": "配字用于指出对方前后说法矛盾，语气偏调侃。",
  "use_cases": ["承认错误", "指出自相矛盾"],
  "avoid_cases": ["严肃道歉", "安慰悲伤"],
  "classification_confidence": 0.88
}
```

约束：

- `primary_category` 必须是 12 个主分类之一；无法可靠判断时为空并标记为待重新整理，不强行归类。
- `semantic_tags` 最多保留 2 个，仅用于辅助描述、管理页面和候选提示，不参与自动发送分类路由。
- `semantic_summary` 是一到两句自然语言，必须说明画面表达的态度、语气或使用意图。
- `visible_text` 保存图片中可见原文；没有文字时为空字符串。
- `text_meaning` 解释配字的语用含义，不把 OCR 原文误当成完整语义。
- `use_cases` 与 `avoid_cases` 各保留少量短语，帮助 outgoing 模型排除“情绪分类相同但语境不适合”的图片。
- 保留旧 `tags` 字段作为兼容数据，不再让它决定自动发送候选；新逻辑使用 `primary_category`。

## 数据流

### 入库与重新索引

视觉索引提示从“最多 5 个固定标签”改为同时输出主分类、最多 2 个辅助标签和语义字段。批量和单图索引使用相同字段契约，索引版本和 prompt 版本递增，确保旧结果会被识别为过期并重新整理。

旧 catalog 迁移遵循以下顺序：

1. 已有合法 `primary_category` 时保留。
2. 没有该字段但存在合法 `category` 时，将其通过别名归一化为主分类。
3. 只有一个可归一化旧标签时可暂时推断主分类。
4. 多个冲突标签或无法推断时保留原数据，但 `primary_category` 为空并标记 `needs_reindex`，不进入自动发送。

迁移不删除旧标签、不移动图片、不伪造低置信度分类。重新索引完成后才会填充完整语义字段。

### 自动发送

outgoing 选图流程改为：

1. 情景模型从 12 个主分类中选择是否发送及主分类。
2. 存储层只从 `primary_category` 完全匹配的已索引图片中建立候选集合。
3. 模型使用 `semantic_summary`、`visible_text`、`text_meaning`、`use_cases`、`avoid_cases` 选择具体 `candidate_id`。
4. 发送次数权重只在最终候选集合内生效。

辅助标签只作为提示上下文，不得把图片扩散到其它主分类。原有 tag lookup 可继续服务 WebUI 和兼容查询，但自动发送不再读取 `by_tag` 作为主分类候选源。

## 错误处理与兼容性

- 旧 catalog 缺少新字段时保持可读；无法推断主分类的条目继续可在管理页面查看，但自动发送跳过。
- 视觉模型返回未知主分类、超过 2 个辅助标签或非法结构时，按索引失败处理并保留旧条目，等待下一次重试。
- outgoing 模型返回旧格式时，允许按主分类回退，但不允许通过辅助标签扩大候选范围。
- 不增加新的外部依赖，不恢复已退役的向量语义启动路径。

## 测试计划

- 主分类归一化只接受 12 个主分类及既有别名。
- 辅助标签最多 2 个，旧 `tags` 不会改变 `primary_category`。
- 带错误辅助标签的图片不会出现在其它主分类的自动发送候选中。
- 多标签冲突的旧条目被标记为 `needs_reindex` 并从自动发送中排除。
- outgoing 提示包含语义描述和图片文字含义，并且 `candidate_id` 约束最终文件。
- 索引版本变化会触发旧数据重新整理。
- 更新 `metadata.yaml`、README 版本徽章和 CHANGELOG 到 `v2.1.5`。
- 运行相关单元测试、完整 unittest、compileall、配置 schema 检查、架构检查和 `git diff --check`。

## 非目标

- 本版本不引入 embedding、FAISS 或其它向量检索。
- 本版本不删除旧标签数据，不重命名图片，不修改 WebUI 的历史标签管理接口。
- 本版本不要求发送前重新执行 OCR；发送使用索引阶段保存的视觉语义。
