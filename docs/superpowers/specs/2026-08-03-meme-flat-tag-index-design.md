# 平铺表情包与规范标签索引设计

日期：2026-08-03

## 目标

将表情包从“一个图片只能属于一个分类目录”改为“一个图片可以拥有多个规范标签”。每个资源包只保留一个平铺的 `memes/` 图片目录，图片使用稳定的 `meme_<sha256前12位>.<ext>` 文件名。重索引操作负责把旧分类目录迁移为平铺结构、重建统一索引，并可重复执行。

本次变更必须满足：

- 旧的 `memes/<category>/` 图片可以自动迁移，不丢失描述、情绪、文字、标签、哈希和发送统计。
- 旧目录名会作为迁移图片的初始标签，但不再作为运行时分类依据。
- 新标签必须来自固定的规范词表，简洁、可归一化、可准确调用；模型不能自由创造长句标签。
- 自动发送、采集流程和两个索引管理页都使用统一标签索引。
- 重索引不调用视觉模型，必须在锁内执行且幂等；重复执行不产生重复图片或重复标签。
- 不删除未知文件；只在迁移成功后删除受管的旧索引文件和空目录。

## 方案选择

采用“平铺图片 + 一个统一 `memes/index.json`”方案。

不采用每张图片 sidecar JSON，因为会使文件数量翻倍，并增加上传、预览、备份和清理的同步边界；不采用每个标签一份虚拟索引，因为多份标签索引会增加标签修改和重索引时的一致性风险。

## 规范标签模型

### 规范词表

新增标签规范化模块，提供固定标签、别名和归一化函数。规范标签使用短词或短语，建议长度为 2–6 个汉字；每张图片最多保留 5 个核心标签。词表按“情绪、态度、动作、场景”组织，但存储时仍是一个扁平数组。

初始词表至少覆盖：

- 情绪：`开心`、`愤怒`、`悲伤`、`震惊`、`疑惑`、`尴尬`、`害怕`、`期待`、`无语`
- 态度：`赞同`、`拒绝`、`嘲讽`、`嫌弃`、`感谢`、`道歉`、`安慰`
- 动作：`催促`、`围观`、`吃瓜`、`摸鱼`、`庆祝`
- 场景：`工作`、`加班`、`睡觉`、`早安`、`求助`、`发钱`
- 保底：`其他`

词表应允许后续扩展，但运行时输出必须始终归一化到规范名称。别名示例：`生气`、`发火`归一化为 `愤怒`；`吃惊`、`意外`归一化为 `震惊`。无法归一化的模型输出丢弃；若没有有效标签则使用 `其他`。

规范化函数需要完成：拆分逗号/顿号/空白分隔值、去除空白、别名映射、大小写/全半角归一化、去重、最多保留 5 个标签，并保证结果稳定排序。已有用户手工标签应尽量保留；无法映射的旧自由标签可进入迁移报告，但不能直接成为运行时候选标签。

### 模型契约

视觉索引和采集提示词要求模型只从规范词表选择 `tags`，返回短标签数组，不返回标签解释或句子。`emotion` 可继续保留为单个主要情绪字段，但发送筛选以规范 `tags` 为准。

情景发送模型不再返回 `category`。它返回 `should_send`、`tags`（可为空）和 `candidate_id`；服务先按标签交集过滤候选，再用 `candidate_id` 或模型结果完成最终选择。明确的旧分类标记会被当作标签别名解析，以兼容现有消息格式。

## 平铺存储与统一索引

### 文件布局

迁移后的资源包结构为：

```text
<pack>/
  memes/
    meme_<hash前12位>.png
    meme_<hash前12位>.gif
    index.json
    README.md
```

统一 `memes/index.json` 使用版本 2：

```json
{
  "version": 2,
  "updated_at": 0,
  "items": [
    {
      "id": "meme_0123456789ab",
      "filename": "meme_0123456789ab.png",
      "sha256": "完整64位sha256",
      "tags": ["愤怒", "震惊"],
      "description": "",
      "emotion": "愤怒",
      "text": "",
      "indexed": true,
      "send_count": 0,
      "last_sent_at": 0
    }
  ]
}
```

`category` 不再是运行时必需字段。迁移来源可以保存在 `legacy_categories` 中用于追踪，但发送、筛选和提示词不得依赖它。统一索引的图片路径始终是 `memes/<filename>`。

### 保存与去重

`MemeStore.save_image` 改为接收标签而不是分类目录。图片写入 `memes/`，文件名由内容 SHA-256 生成；前缀冲突时依次扩展到 16、20、24、32、64 位。相同 SHA-256 只保留一张图片，重复保存时合并标签并保留已有富元数据。

所有索引写入继续使用现有原子写入工具。统一索引和 README 的更新必须在同一 pack 锁内完成；临时改名必须使用隐藏临时文件，避免目标冲突和半迁移状态。

## 重索引迁移流程

新增 `MemeStore.reindex_flat_catalog()`，并让索引页的重索引 API 调用它。流程如下：

1. 获取 pack 锁，扫描 `memes/` 下所有受支持图片；直接位于 `memes/` 的图片和旧子目录图片都纳入扫描。
2. 对每张图片计算 SHA-256，读取旧目录 `index.json` 中同文件名的元数据。
3. 合并标签来源：旧目录名、旧条目 `tags`、可归一化的 `emotion`；按规范词表归一化并去重。
4. 对相同 SHA-256 的重复文件合并元数据：优先保留非空描述/文字/情绪，标签取并集，发送统计取较大的累计值。
5. 生成稳定 `meme_<hash前缀>.<ext>` 目标名。先改到临时文件名，再改到目标名；目标已存在且内容相同则删除重复源文件，内容不同则扩展 hash 前缀。
6. 按稳定文件名写入统一 `memes/index.json`，保留索引状态和发送统计；生成统一 README。
7. 只有在统一索引写入成功后，才删除旧目录中的受管 `index.json`、`README.md`，并删除空的旧分类目录。目录内有未知文件时保留并报告跳过。
8. 返回 `processed`、`total`、`migrated_file_count`、`deduplicated_file_count`、`tag_count` 和 `skipped_path_count`。重复执行应返回零迁移/去重变更，同时保持索引内容稳定。

迁移失败时保留源文件和旧索引，不清理旧目录；错误响应不得泄漏绝对路径或 traceback。

## 运行时数据流

### 采集

采集流程不再先让模型选择唯一分类。图片先进入平铺目录，视觉识别直接返回描述、主要情绪、文字和规范标签；场景模型只能补充规范标签。保存时通过统一索引记录标签，重复图片走同一 SHA-256 去重与标签合并流程。

### 自动发送

`MemeSelectionService` 从统一索引读取已索引图片。候选上下文包含 `candidate_id`、规范标签、简短描述和发送统计，不包含旧分类目录。若消息带有旧分类标记，先做标签别名归一化。

筛选顺序为：

1. 使用明确请求标签过滤候选；
2. 使用情景模型返回的规范标签计算交集得分；
3. 在最高得分候选中按现有重复发送衰减权重随机选择；
4. 没有标签命中时才在全体已索引候选中选择，避免因单一标签误判导致完全不发送。

发送日志和决策结果将 `category` 字段替换为 `tags`，保留短期兼容读取，禁止新代码重新依赖分类目录。

## Web 索引页与 API

`CaptureIndexAPIMixin` 的 workspace 接口改为返回：

- `tags`：标签及图片数量的汇总列表
- `indexed_items`、`pending_items`：统一索引中的图片条目
- `summary`：索引、待处理、重复、标签和文件总数
- `library_index`：当前重索引/识别进度

查询参数从 `category` 增加并逐步替换为 `tag`；`tag` 使用规范标签校验。为旧页面保留 `category` 参数兼容解析，但只将其当作标签别名，不再遍历目录。

两个索引页面都改为展示“全部 + 标签 chips”，卡片显示 `meme_xxxx` 文件名、标签、状态、描述和缩略图。重索引按钮触发平铺迁移并显示当前来源目录、已处理数、总数、迁移数和去重数。重索引期间按钮和进度轮询行为保持现有契约。

图片预览接口新增平铺路径参数契约，只允许读取 `memes/` 直接子文件；不允许通过 `../` 或目录参数访问根目录外文件。

## 兼容与边界

- 旧 pack 在未重索引前仍可读取，启动或索引页首次重索引时完成迁移；不再创建新的分类目录。
- 旧的分类描述配置仅用于迁移别名和兼容展示，不再生成分类候选列表。
- 旧的 per-category `index.json` 只作为迁移输入；统一索引成功后不再更新它。
- 不支持的文件、目录外路径、非法文件名和坏索引条目跳过并计数，不中断其他图片迁移。
- 统一索引为空时 WebUI 显示空状态；没有可用规范标签时使用 `其他`。

## 验证策略

新增或更新测试覆盖：

- 标签别名归一化、去重、上限和 `其他` 保底。
- 旧分类目录迁移为平铺文件，旧目录名成为标签。
- 稳定 hash 文件名、前缀冲突、重复图片合并和重索引幂等。
- 描述、标签、哈希、索引状态和发送统计迁移后保留。
- 采集保存、统一索引读取、标签筛选和自动发送候选选择。
- 重索引 API 的进度、错误回滚和未知文件保留。
- 两个索引页的标签 chips、平铺预览路径、重索引按钮和进度文本。
- Python 全量测试、Node 语法检查和 `git diff --check`。
