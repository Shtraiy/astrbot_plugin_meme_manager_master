# 表情包偷取评分门槛设计

## 目标

降低表情包偷取流程对普通日常图片、截图和信息图片的误收录率。视觉模型必须输出 `meme_score`，系统以严格评分门槛和已有硬拒绝规则共同决定图片是否进入资源包；不合格图片直接丢弃，不进入待分类或待重索引列表。

## 当前问题与根因

当前捕获流程已经检查 `is_meme`、`confidence`、`content_type` 和截图/照片等排除标记，但没有独立的“可作为聊天表情包使用”评分。模型在内容类型判断偏宽时，普通照片可能仍然带着 `is_meme=true` 和允许的 `content_type` 通过门槛，随后被保存并进入待分类索引。

本次改动只收紧“偷取识别”阶段，不改变已有资源包中的图片，也不把 v4 语义索引版本升级为新的版本。

## 设计方案

### 1. 统一视觉识别输出

单图和批量偷取使用同一套评分契约。模型响应必须包含：

```json
{
  "is_meme": true,
  "confidence": 0.92,
  "meme_score": 86,
  "content_type": "reaction_meme",
  "has_expression": true,
  "is_screenshot": false,
  "is_chat_screenshot": false,
  "is_document": false,
  "is_ui": false,
  "is_photo": false,
  "is_webpage": false,
  "is_poster": false,
  "is_banner": false,
  "is_receipt": false,
  "rejection_reason": "",
  "description": "简短中文描述",
  "emotion": "情绪",
  "text": "图片中的文字"
}
```

`meme_score` 表示图片作为聊天表情包被重复使用的可能性，范围为 `0–100`。提示词必须明确以下正向证据：明显人物/角色/动物与情绪或动作、短文字/字幕/梗文字、主体突出且构图简单、可作为上一句话的反应、脱离原场景仍可复用、常见 meme/reaction image/二次元表情/熊猫头等。

提示词必须明确以下负向证据：普通照片/自拍/风景、游戏/软件/网页/聊天记录截图、二维码、商品图、教程图、数据图、报错图、海报/广告、单纯动漫或影视截图、主要用于传递具体信息的图片。消息文本只能辅助理解，不能把普通信息图片提升为表情包。

模型无法确认时必须给低分并拒绝；`rejection_reason` 继续用于说明拒绝原因。批量响应中的每个 `items` 项都必须包含 `meme_score`。

### 2. 严格保存门槛

新增固定门槛 `MEME_SCORE_THRESHOLD = 70`。在 `should_skip_meme_result` 中按以下顺序执行：

1. `vision` 必须是映射且不能是视觉模型错误结果。
2. `is_meme` 必须为可识别的布尔值且为 `true`。
3. `confidence` 必须是有限的 `0–1` 数字，并继续满足现有运行时 `meme_rejection_confidence` 配置。
4. `meme_score` 必须是有限的 `0–100` 数字；允许模型返回数字字符串，但拒绝布尔值、空值、NaN、无穷值和越界值。
5. `meme_score` 必须大于等于 `70`；低于 `70` 的图片直接返回跳过。
6. `content_type` 必须属于现有允许集合；普通照片、截图、文档、网页、UI、海报、横幅、收据等拒绝类型继续硬拒绝。
7. 现有截图/聊天截图/文档/UI/照片/网页/海报/横幅/收据标记和 `has_expression=false` 继续硬拒绝。

因此，评分处于 `0–69` 的图片不会落入“待重索引”灰区，而是直接以 `not_meme` 结果结束，不保存文件、不创建捕获活动记录。

### 3. 记录与兼容性

通过识别并保存的图片在捕获目录条目中记录规范化后的 `meme_score`，用于后续诊断和 WebUI 展示；拒绝图片不写入资源包目录。该字段不作为当前 v4 完整索引契约的必填字段，因此不会让历史图片因缺少 `meme_score` 而自动全部失效，也不修改 `LIBRARY_INDEX_VERSION`。

黑名单和重复检测逻辑保持不变：黑名单仍然在视觉识别前拦截，精确/感知重复仍在保存阶段处理。

本次不自动清理已经进入资源包或待重索引列表的旧误收录图片，避免未经确认删除用户数据；旧图片继续通过 WebUI 的忽略/删除操作处理。

## 测试与验收标准

- `should_skip_meme_result` 接受：`is_meme=true`、合法 `content_type`、现有置信度合格、`meme_score=70` 或更高且无拒绝标记。
- `should_skip_meme_result` 拒绝：`meme_score=69`、缺失、布尔值、非数字、NaN、无穷值和越界值。
- 普通照片、自拍、风景、游戏/网页/聊天截图、文档、二维码、商品图、教程图、数据图、报错图和无明确表情包用途的动漫/影视截图在任意高 `confidence` 下仍被拒绝。
- 单图和批量视觉提示词都包含 `meme_score`、`0–100` 范围、正向特征和负向特征，并要求无法确认时拒绝。
- 捕获流水线不会为低分图片调用分类保存路径；高分合法图片仍可进入原有分类和保存流程。
- 已保存捕获条目保留规范化 `meme_score`，现有 catalog/v4 重索引测试不受影响。
- 完整回归继续通过：页面 JavaScript 检查、Python 编译、架构检查、schema 同步、差异检查和全部单元测试。
