# 表情模型配置与重索引工作台设计

日期：2026-08-03

## 目标

- 设置中只保留识图模型和情景识别模型；自动回复情景判断复用情景识别模型。
- 为 Web 表情索引页增加“重索引”能力，只重新编号本地文件并同步 `index.json`，不调用模型。
- 索引页按分类筛选表情，使用上下两块展示已索引与待处理项目，并为卡片提供缩略图。

## 设计

### 模型配置

移除 `reply_scene_provider_id` 的配置字段、类型字段和设置 schema。情景发送选择统一读取 `scene_provider_id`。旧配置中的同名字段不再参与运行时决策；其他后台索引模型配置保持不变。

### 重索引

新增 pack-scoped 的重索引 API。API 接收页面当前选择的资源包，使用该资源包的目录锁，逐分类执行：

1. 按现有文件名的稳定顺序读取图片；
2. 使用临时文件名将图片改名为 `<category>_0001.<ext>`；
3. 将原 catalog 条目的 `filename` 和 `id` 映射到新文件名；
4. 保留描述、情绪、标签、哈希、索引状态和发送统计；
5. 原子写回 `index.json` 与 README。

此流程不读取模型配置、不调用 LLM，也不改变分类或索引状态。

### 索引页

两套现有索引入口保持同一行为：顶部提供资源包、刷新、重索引和待处理索引操作；分类 chips 作为筛选器；主体上下排列为已索引区和待处理区。选择分类后，页面请求该分类的完整条目，卡片显示缩略图、文件名、状态和描述，点击仍打开原图预览。

## 验证

- 配置 schema 和运行时字段不再出现 `reply_scene_provider_id`。
- 重索引测试确认缺号被补齐、catalog 元数据保留、索引状态不变且不产生模型调用。
- 两套页面均包含重索引按钮、分类筛选、上下布局和 preview 缩略图契约。
- Python 全量测试、Node 语法检查和 `git diff --check` 通过。
