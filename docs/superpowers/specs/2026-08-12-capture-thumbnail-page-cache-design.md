# 表情索引工作台页面内缩略图缓存设计

## 目标

优化表情索引工作台在当前浏览器页面生命周期内的缩略图加载。首次出现的图片仍通过现有接口生成缩略图；同一图片在刷新工作区、处置项目、切换筛选或翻页返回时直接复用内存中的 Data URL，不再重复读取文件、生成缩略图和传输 JSON。

用户按 F5 或重新进入页面后允许重新加载全部缩略图。本改动不引入磁盘缓存、Service Worker 或新的后端缓存层。

## 问题与原因

两套工作台脚本的 `renderWorkspace` 每次收到工作区数据时都会清空卡片容器并重新创建所有卡片。`renderCard` 随后无条件调用 `loadThumbnail`，而 `loadThumbnail` 每次都请求 `meme_image_data?size=preview`。

后端会为每个请求重新打开源文件，并使用 Pillow 生成预览 Data URL。因为图片内容包含在 JSON 响应中，而不是作为具有 HTTP 缓存头的图片资源返回，所以浏览器自身的图片缓存不能消除这些重复接口调用。这使刷新、忽略和翻页返回都出现整批缩略图重新加载的等待。

## 缓存模型

每套工作台脚本维护两个页面级 Map：

- `thumbnailCache` 保存已经成功取得的 Data URL，并用 Map 的插入顺序实现 LRU。
- `thumbnailRequests` 保存正在进行的 Promise，同一图片并发出现时只发出一次接口请求。

缓存命中时，将条目从 Map 中删除后重新插入，更新其最近使用顺序。缓存未命中时，先检查是否已有相同键的请求；有则复用 Promise，没有则创建请求。请求成功后写入 LRU，失败或响应无效时不写缓存，并始终从 `thumbnailRequests` 删除，保证用户点击重试会真正再次请求。

## 缓存键

缓存键必须包含当前资源包，避免不同资源包中同名文件互相污染：

1. 项目具有合法 SHA-256 时，使用 `pack_id + sha256`。
2. 其他项目使用 `pack_id + relative_path`。
3. `relative_path` 不可用时，使用后端图片定位参数中的 `category + filename` 作为保底。

重复记录提供 SHA-256，因此同一内容的多张重复卡片能够共享一次请求。普通已整理和待分类项目当前不提供 SHA-256，它们使用资源包内稳定的相对路径；重建索引后会清空缓存，避免文件重命名或原位替换后继续显示旧内容。

## 加载流程

`loadThumbnail` 保留现有卡片状态和重试交互，但改为通过统一的 `getCachedThumbnail` 获取 Data URL：

1. 计算图片定位和缓存键。
2. 命中成功缓存时立即设置 `img.src`，不调用 API。
3. 命中进行中请求时等待同一个 Promise。
4. 未命中时调用现有 `meme_image_data` 预览接口。
5. 仅在响应包含有效 Data URL 时加入缓存。
6. 卡片可能在异步请求期间被完整重绘；旧卡片完成加载不会影响新卡片，新卡片可复用同一个进行中请求或成功缓存。

因此，忽略或删除一张图片后重新绘制当前页时，原本仍在页面上的卡片不再请求缩略图；只有从下一页补入的全新卡片需要首次加载。翻到新页仍会加载该页首次出现的图片，返回已经看过的页面则直接复用缓存。

## 容量与生命周期

缓存同时设置两个上限：

- 最多 512 个成功条目。
- 按 JavaScript 字符串每字符约 2 字节估算，最多 64 MiB。

加入新条目后，从最久未使用的条目开始逐个淘汰，直到同时满足两个上限。进行中的 Promise 不计入成功缓存容量，也不因 LRU 淘汰而取消请求。

以下操作不清空缓存：

- 手动刷新当前工作区数据。
- 单项或批量忽略、删除后的完整工作区重绘。
- 标签筛选切换。
- 已整理区翻页。

以下操作执行显式失效：

- 切换资源包时清空全部成功缓存和可安全遗弃的请求引用。
- 重建索引成功后清空全部缓存，再加载新的工作区。
- 已整理或普通待分类文件处置成功后，移除对应文件的成功缓存；删除失败不失效，以便失败卡片继续即时显示。
- 重复记录“忽略并拉黑”保留资源包中已有图片，因此不主动逐项删除其缓存。
- 页面卸载后由浏览器自然释放全部内存。

切换资源包时已开始的旧请求可能仍完成，但请求完成时必须验证它所属的资源包仍与请求创建时一致；不允许把旧资源包结果重新写入已清空的缓存。

## 预览与后端边界

缓存只服务卡片缩略图。点击卡片打开原图预览时继续调用现有原图接口，避免用高分辨率 Data URL 快速耗尽页面内存，也保证预览读取当前文件。

后端 `meme_image_data` 接口和图片处理逻辑保持不变。本次不新增公开配置项、不修改 `_conf_schema.json`、不提升插件版本号。

## 两套页面同步

以下文件保持相同的缓存行为，同时保留各自现有的导航与页面差异：

- `pages/semantic/script.js`
- `pages/a_manage/semantic/script.js`

修改脚本后同步更新两套 HTML 中该脚本的缓存版本参数，确保 AstrBot WebUI 不继续使用旧脚本。CSS 无变化时不更新样式版本。

## 测试与验收

JavaScript 运行时回归测试记录 `meme_image_data` 的请求次数，并覆盖：

- 初次渲染只为每个唯一可见图片发出一次请求。
- 完整刷新相同工作区后，请求次数不增加。
- 忽略或删除后，保留卡片全部命中缓存，只有新补入卡片增加一次请求。
- 翻到新页会加载新图片，返回已浏览页面不增加请求。
- 同一图片的并发卡片共享一个进行中的 Promise。
- 加载失败不进入缓存，点击重试会再次发出请求。
- 切换资源包和重建索引成功会清空缓存。
- 成功删除文件会失效对应条目；删除失败和只忽略重复记录不会错误失效。
- 超过条目数或估算字节上限时，优先淘汰最久未使用条目。
- 两套页面的脚本和缓存版本保持同步。

实现完成后运行目标 JavaScript 运行时测试、全量 `unittest`、全部 JavaScript `node --check`、`compileall`、配置 schema 检查、架构检查和 `git diff --check`，并在 `CHANGELOG.md` 的 `[Unreleased]` 中记录页面内缩略图复用优化。

## 不在本次范围内

- 跨 F5、跨标签页或跨浏览器会话的持久缓存。
- 后端磁盘缩略图缓存和 HTTP 缓存协议改造。
- 原图预览缓存。
- 缓存容量的用户配置界面。
