# 表情包持久化加权随机设计

## 目标

让表情包发送更加均衡：同一张图片成功发送次数越多，后续被选中的权重持续下降；长时间未发送的图片逐步恢复权重，从而提高其他图片被发送的机会。

统计范围覆盖 `meme_manager_master` 发出的所有表情包，包括自动情景发送、明确指令发送和偷取后主动发送。统计在当前表情包库内全局累计，不按群聊拆分。

## 现状与范围

当前项目已经具备候选图片加权选择、成功发送标记和 `send_count`/`last_sent_at` 字段的部分实现。本次工作补齐并明确其长期次数惩罚，确保所有发送路径和失败语义一致，并用回归测试固定行为。

保留现有流程：情景模型先决定分类，存储层再从该分类的已索引图片中进行加权随机选择。不修改模型提示词、分类判断、自动发送概率、发送冷却或 WebUI 配置范围。

## 数据模型

每个图片目录索引条目持久化：

- `send_count`：成功发送累计次数，默认 `0`；
- `last_sent_at`：最近一次成功发送的 Unix 时间戳，默认 `0`。

旧条目缺少字段时按从未发送处理。重建索引、迁移目录和重复图片合并时保留已有统计字段。

## 权重算法

对每个候选图片计算：

```text
count_factor = 1 / (1 + 0.35 * send_count)
recovery_factor = 0.35 + 0.65 * min(age / repeat_window, 1)
weight = max(0.1, count_factor * recovery_factor)
```

其中 `age = max(0, now - last_sent_at)`。`repeat_window` 沿用现有 `meme_repeat_window` 配置，默认值为 300 秒；当该配置不大于零时，跳过时间衰减并返回基础权重。

算法保证：

- 未发送图片权重为 `1.0`；
- 累计发送次数增加时，权重持续下降，不设“四次后停止惩罚”的上限；
- 一个完整冷却窗口后，时间因素恢复，但累计次数因素仍保留；
- 最低权重为 `0.1`，不会永久饿死图片；
- `random.choices` 使用相对权重，因此同分类内其他图片获得更高概率。

## 发送成功标记

图片只有在实际发送成功后才更新统计：

1. 选择图片时只读取权重，不修改索引；
2. 发送动作成功返回后调用统一记录方法；
3. 记录方法递增 `send_count`、写入 `last_sent_at`，并通过现有原子目录索引写入流程持久化；
4. 发送失败、候选选择失败、图片不存在或只锁定候选但尚未发送时不更新统计。

所有本插件发送路径统一接入该记录方法。已有的异步保存锁继续用于避免并发目录写入丢失。

## 异常与兼容性

- 无法解析的历史统计值按默认值处理；
- 不改变已有图片的文件名、索引结构或分类标签；
- 不增加新的配置项，避免 WebUI 和配置迁移扩大；
- 无候选图片时保持现有返回 `None` 行为；
- 记录统计失败不能伪造发送成功，保留日志并不影响消息发送结果。

## 测试设计

新增或补充纯存储层测试，覆盖：

- 发送次数增加时权重单调下降；
- 时间经过 `repeat_window` 后权重恢复到仅受次数影响的水平；
- 最低权重生效；
- 缺少字段和非法字段使用默认值；
- `mark_image_sent` 成功更新次数和时间并写回索引；
- 不存在或越界路径不会写入统计；
- 现有发送流程测试确认成功发送打标、失败发送不打标。
