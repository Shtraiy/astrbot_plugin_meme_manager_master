# 普通情绪对话主动发表情设计

## 目标

修复普通对话中的情景模型把“用户未明确索要表情包”当成拒绝发送理由的问题。
明确请求仍然强制发送，但不再是普通自动发送的必要条件。

## 已确认根因

现有情景提示词重点强调：

- `explicit_request=true` 时必须发送。
- JSON 格式示例固定使用 `should_send=false`。

实际运行日志显示，面对“我教出了一个神”以及机器人带明显惊讶情绪的回复，
模型仍返回：

```text
should_send=false
reason=用户未明确索要表情包
```

这证明模型把“明确请求时强制发送”误读成了“只有明确请求才能发送”。代码随后
在概率与实际发送阶段之前直接返回，因此表情包不会进入发送队列。

## 修复方案

采用提示词契约修正，不取消情景判断：

1. 明确普通聊天可以主动发表情，不需要用户先索要。
2. 明确 `explicit_request=false` 只表示不是强制请求，不代表禁止发送。
3. 禁止仅以“用户未明确索要”为理由返回 `should_send=false`。
4. 对惊讶、开心、赞叹、调侃、吐槽、安慰、尴尬、无奈等明显社交情绪，
   优先返回 `should_send=true` 并选择匹配分类。
5. 仅在纯事实说明、长篇严肃内容、错误提示或完全无情绪时返回
   `should_send=false`。
6. 移除固定为 `false` 的 JSON 示例，改为字段约束，避免模型照抄默认值。

## 代码边界

将发送决策提示词移到无 AstrBot 运行依赖的 `collector.py`，作为可直接测试的
纯文本边界；`capture.py` 导入并使用该提示词。发送流程本身保持不变：

- 情景模型先判断并选择分类。
- 模型允许发送后，继续执行冷却时间检查。
- 普通对话继续执行 `auto_send_probability` 概率检查。
- 明确请求继续覆盖模型拒绝、冷却和普通概率门控。
- 最终仍从已有分类索引中选择本地图片并在正文发送后发送。

不恢复已经退役的向量语义启动任务，也不修改表情收集、索引、健康检查或
AstrBot 生命周期逻辑。

## 测试

新增纯单元测试验证发送提示词契约：

- 包含“普通对话无需明确索要也可主动发送”的规则。
- 明确 `explicit_request=false` 不代表禁止发送。
- 禁止把“未明确索要”作为唯一拒绝原因。
- 包含惊讶等正向自动发送场景。
- 不再包含固定 `should_send=false` 的 JSON 输出样例。
- 保留 `explicit_request=true` 时强制发送规则。

测试按 RED → GREEN 执行，再运行完整 `unittest` 套件、Python 编译检查和差异
格式检查。

## 验收

使用 `auto_send_probability=100`、`auto_send_cooldown=0` 验证普通情绪场景时，
类似下面的日志应从拒绝变为允许发送：

```text
[meme_manager_master] 情景分析决定发送 category=... confidence=... reason=...
[meme_manager_master] 已锁定表情包，等待正文发送完成 source=scene ...
[meme_manager_master] 正文发送完成后发送自动表情包 path=...
```

中性事实说明仍允许模型返回不发送；明确索要表情包仍然必须发送。
