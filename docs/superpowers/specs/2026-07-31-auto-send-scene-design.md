# 自动发送情景判断设计

## 背景

当前自动发送流程先执行 `auto_send_probability`，只有概率命中后才调用情景模型。默认概率为 35% 时，大部分正常回复不会进入情景判断，导致日志中看不到情景识别，实际发送率也被“概率拦截 + 模型判断”双重降低。

## 目标

- 每条启用自动发送的正常回复都先经过情景模型判断。
- 情景模型判断“不适合发送”时，不发送表情包。
- 情景模型判断“适合发送”后，继续使用冷却时间和发送概率限制频率。
- 明确索取表情包的请求继续绕过自动发送概率。
- 不改变表情包偷取、索引、分类和 WebUI 逻辑。

## 处理流程

```text
正常回复
  -> 基础条件检查
  -> 情景模型判断
  -> 不发送：结束
  -> 发送：检查冷却时间
  -> 检查自动发送概率
  -> 抢占事件发送锁
  -> 选择并发送表情包
```

明确索取表情包的请求继续使用强制发送路径，不受自动发送概率影响。

## 错误处理

情景模型不可用、返回无法解析或没有可用索引时，保持不发送并记录已有日志；自动发送概率只在情景模型给出发送意图后生效。

## 测试

- 增加回归测试，保证情景选择调用位于自动发送概率判断之前。
- 保留现有明确请求、冷却、索引选择和存储测试。
- 执行完整 Python 测试、Python 编译检查和 JavaScript 语法检查。
