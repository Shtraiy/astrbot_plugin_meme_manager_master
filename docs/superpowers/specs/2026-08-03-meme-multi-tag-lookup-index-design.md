# 表情包多标签去重与快速调用索引设计

## 背景

当前表情包已经使用平铺目录保存图片，并在 `memes/index.json` 中保存图片元数据。一个图片条目可以拥有多个固定标签，旧分类目录迁移时也会按图片摘要去重并合并标签。

仍存在三个问题：

1. 标签上限是 5 个，需要提升为 6 个。
2. 重复图片在采集流程中可能在视觉分类前提前返回，导致这一次识别出的新标签没有合并到已有条目。
3. Bot 选图和部分管理操作反复扫描完整主索引，没有专门的按标签候选索引。

## 目标

- 同一图片只保留一个实际文件。
- 同一图片最多拥有 6 个现有固定标签，标签去重、规范化并保持稳定顺序。
- 精确重复图片始终按 SHA-256 合并；现有可选感知哈希去重能力继续保留。
- 新增可恢复的按标签快速查找索引，供 Bot 选图使用。
- 现有旧目录、旧主索引和既有 WebUI 行为保持兼容。
- 删除或移除标签时只改变标签关系；只有明确删除图片时才删除实际文件。

## 非目标

- 不引入 SQLite 或其他外部数据库。
- 不开放任意自定义标签；仍使用 `backend/tagging.py` 中的固定词表和别名映射。
- 不改变感知哈希阈值的配置语义。
- 不把一个图片复制成多个标签目录中的文件。

## 数据模型

### 主索引

`memes/index.json` 继续作为完整事实来源。每张图片只有一个条目，关键字段包括：

```json
{
  "id": "meme_<sha256前12位>",
  "filename": "meme_<sha256前12位>.png",
  "sha256": "...",
  "tags": ["开心", "嘲讽"],
  "indexed": true,
  "send_count": 0,
  "last_sent_at": 0
}
```

`tags` 由统一的 `normalize_tags()` 生成，最多 6 项。已有描述、情绪、文字、识别状态和发送统计在合并时保留；新值只有在有意义时覆盖空值或按现有索引流程更新。

### 派生快速索引

新增 `memes/tag_index.json`，它不是第二份图片元数据，而是从主索引派生的候选映射：

```json
{
  "version": 1,
  "source_version": 2,
  "source_updated_at": 0,
  "updated_at": 0,
  "by_tag": {
    "开心": ["meme_abc123456789"],
    "嘲讽": ["meme_abc123456789"]
  },
  "items": {
    "meme_abc123456789": {
      "filename": "meme_abc123456789.png",
      "tags": ["开心", "嘲讽"],
      "indexed": true,
      "send_count": 0,
      "last_sent_at": 0
    }
  }
}
```

`by_tag` 中同一个 ID 可以出现在最多 6 个标签下，但 `items` 只保存一份图片候选信息，因此同图不同标签不会造成候选重复。索引生成时只收录实际存在、扩展名受支持且已完成索引的图片；管理页面仍可从主索引看到待索引条目。

## 写入与一致性

在 `MemeStore` 内集中实现派生索引构建和读取：

- `write_catalog()` 完成主索引规范化后，基于同一批条目重建 `tag_index.json`。
- `save_image()` 发现重复时，调用统一合并逻辑，把传入标签并入已有条目；不再依赖调用方是否先执行过分类目录写入。
- 采集流程先完成本次图片的视觉/场景标签计算，再调用保存/合并逻辑。重复图仍返回 `duplicate`，但新的标签和可用元数据会进入同一条目。
- 标签增删、复制、移动、清空分类、删除图片、批量重索引全部复用主索引写入路径，自动刷新派生索引。
- 主索引和派生索引都使用现有原子写入方式。读取时如果派生索引不存在、版本不匹配、来源时间戳不一致或内容校验不通过，则从主索引同步重建。

不使用两个独立的增量写入操作来维护 `by_tag`，避免某个异常造成标签索引残留旧 ID。

## Bot 调用路径

`pick_indexed_image()` 首先读取 `tag_index.json`：

1. 将请求标签规范化。
2. 从对应 `by_tag` 桶取得去重后的候选 ID；没有标签限制时合并所有桶。
3. 从 `items` 解析文件名、索引状态和发送统计。
4. 检查文件仍存在后，沿用现有重复窗口和发送次数权重随机选择。
5. 派生索引不可用时，回退到主索引并触发重建，不能因为索引文件损坏而阻断 Bot 调用。

## 重复与标签合并规则

- SHA-256 相同：视为同一图片，保留一个平铺文件，标签取已有标签和新标签的规范化并集，最多 6 项。
- 感知哈希命中：沿用现有阈值判断，复用命中的已有文件，并按同样规则合并标签。
- 如果感知哈希命中但 SHA-256 不同，主索引仍记录实际文件的 SHA-256；不创建第二个候选条目。
- 合并不应降低已有的 `indexed` 状态或清空描述、发送统计等非空元数据。
- 标签数量超过 6 时，按固定词表顺序截取前 6 个，保证结果确定且与现有前端/接口一致。

## 迁移与修复

`reindex_flat_catalog()` 继续负责：

- 将旧分类目录的图片迁移到平铺目录。
- 按 SHA-256 合并跨标签重复文件。
- 合并旧条目的标签和非空元数据。
- 最后通过统一写入路径生成 `index.json` 和 `tag_index.json`。

新增一个轻量的派生索引重建入口，供启动恢复、管理页重索引和测试使用。重建应幂等，不改变图片文件内容。

## 测试范围

增加或调整以下测试：

- 标签规范化最多保留 6 个固定标签，并继续去重、别名归一化和稳定排序。
- 同一图片先以标签 A 保存，再以标签 B 保存，磁盘只有一个文件，主索引只有一个条目且包含两个标签。
- 重复图片在采集流程中带来新标签时，已有条目标签会合并。
- 重索引跨旧分类目录的重复图片时，仍只保留一个文件，并生成正确标签集合。
- `tag_index.json` 按标签建立候选桶，同一图片出现在多个桶但 `items` 只出现一次。
- 标签增删、删除图片和清空分类后，派生索引不残留失效 ID。
- Bot 选图优先使用派生索引；派生索引缺失或失效时可从主索引恢复并正常返回图片。
- 保留并运行现有管理页、索引页、上传、复制、移动、删除和发送统计测试。

## 验收标准

- 同一图片无论通过上传、复制、采集或旧目录迁移进入系统，都不会因标签不同产生多个实际文件。
- 一个图片条目的标签最多为 6 个，且所有入口结果一致。
- `tag_index.json` 可独立完成按标签候选查找，损坏或缺失时系统能自动恢复。
- Bot 选图结果与现有标签筛选语义一致，发送频率和重复窗口行为不回归。
- 完成迁移后，主索引、派生索引和实际图片文件数量关系稳定、可重复重建。
