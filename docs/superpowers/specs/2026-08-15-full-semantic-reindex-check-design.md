# 全量语义重索引检查设计

## 背景

当前表情索引页面的“重索引”只负责把旧分类目录整理为 flat 目录、规范文件名并重建标签索引，不会重新调用视觉模型。v2.1.5 已经建立了主分类和语义索引契约，因此旧版 v3 或缺少语义字段的图片需要一个用户可主动触发的全量检查入口。

## 目标

- 将页面“重索引”升级为“目录整理 + 全量语义索引检查”。
- 扫描当前资源包的全部图片，而不是只处理待分类记录。
- 对已有完整 v4 索引的图片跳过视觉模型调用，避免重复消耗模型额度。
- 对旧版、文件内容变化、字段不完整或主分类无效的图片重新识别和分类。
- 为每次检查写入明确的处理标记和时间，便于 WebUI、日志和后续诊断确认跳过/重建结果。
- 不删除图片；单张失败不阻塞其他图片。

## 非目标

- 不在本次功能中引入 OCR、向量数据库或新的外部依赖。
- 不改变自动后台索引的 v4 完整性判断语义，只复用其索引核心。
- 不把旧 `tags` 重新扩展为自动路由分类。

## 方案选择

### 方案 A：复用现有语义索引核心，扩展手动入口（采用）

手动入口先执行现有 flat 目录整理，再调用统一的全量扫描器。扫描器对每个文件执行“当前索引是否完整”的判断，完整项写入跳过标记，其他项进入现有批量/逐图视觉识别流程。优点是复用已有的批量重试、保存、进度和失败处理逻辑，且不会删除旧数据。

### 方案 B：删除索引后重新生成

实现简单，但会在模型调用失败时丢失既有可用语义，且可能让自动选图短时间没有候选，不采用。

### 方案 C：仅增加命令行强制重建

适合维护人员，但无法解决普通用户已经能看到“重索引”按钮却无法完成语义重建的问题，不采用。

## 索引完整性判断

手动全量检查对每个图片条目使用以下条件判断是否可以跳过：

1. `indexed` 为真。
2. `index_version == 4`。
3. `index_prompt_version` 等于当前语义索引提示词版本。
4. 条目的 `sha256` 与当前文件 SHA-256 相同。
5. `primary_category` 是 12 个允许主分类之一，且 `primary_category_status` 不是 `needs_reindex`。
6. 语义字段存在并可归一化：`semantic_summary`、`visible_text`、`text_meaning`、`use_cases`、`avoid_cases`、`classification_confidence`、`semantic_tags`。

provider 仍记录在索引元数据中；手动检查默认沿用当前配置的索引模型。已有完整 v4 结果只要内容和字段契约有效即可跳过，不因单纯重启插件而重复调用模型。

## 处理标记

每次手动全量检查在目录条目上写入：

```json
{
  "full_reindex_status": "skipped_current | reindexed | error",
  "full_reindex_checked_at": 1755221850
}
```

- `skipped_current`：已有完整 v4 索引，本次跳过视觉模型。
- `reindexed`：本次成功完成视觉识别、主分类和语义字段更新。
- `error`：本次识别失败；如果旧条目仍是完整有效索引，保留旧字段以维持可用性；如果旧条目无有效索引，则保持 `indexed=false` 或 `needs_reindex`，不得进入自动发送候选。

标记只描述最近一次手动全量检查，不参与主分类路由，也不替代 `index_version`、文件 SHA 或 `primary_category_status`。

## 数据流

```text
点击“重索引”
  -> 锁定当前资源包
  -> 整理旧分类目录和 flat 文件名
  -> 扫描全部图片并计算 SHA-256
  -> v4 完整条目：写 skipped_current
  -> 旧/过期/字段不完整条目：批量视觉识别
  -> 批量缺失或失败：逐图补偿与重试
  -> 写入主分类、语义字段和处理标记
  -> 重建 tag_index/by_primary_category
  -> 返回 processed/skipped/reindexed/errors 进度
```

扫描期间如果图片集合或内容发生变化，继续沿用现有源签名保护：放弃本轮不一致写入，并提示用户稍后重试，避免覆盖新捕获结果。

## API 与 WebUI

- 保留 `POST capture/reindex` 和 `GET capture/reindex/status` 路由，改变其内部语义为全量语义检查。
- `capture/reindex` 返回/状态新增 `skipped`、`reindexed`、`errors` 计数。
- 页面按钮文案改为“全量重索引”或“全量语义重索引”，确认弹窗明确说明：会检查整个资源包，已有完整 v4 索引会跳过，旧索引会重新调用视觉模型。
- 进度显示 `processed/total`，并同时展示跳过、重新识别和失败数量。
- 原有“分类索引待处理项”继续保留，用于只处理后台发现的待分类项；两种任务不能并发。

## 错误与并发

- 无索引模型配置时，任务立即进入 error/blocked 状态并给出配置提示。
- 单批失败时沿用现有逐图补偿；单图失败只增加 errors，不中断整包。
- 全量任务使用已有资源包锁和 `_library_task` 冲突保护，防止与后台索引同时写 catalog。
- 任务完成后统一重建 tag index；任何 `needs_reindex` 或 error 条目都不会进入 `by_primary_category`。

## 测试

- 单元测试：完整 v4 条目被跳过并写入 `skipped_current`。
- 单元测试：v3、SHA 变化、缺少语义字段和无效主分类会进入重新识别。
- 单元测试：成功/失败计数和条目标记正确，失败旧索引保留规则正确。
- API 测试：全量任务状态包含 processed/total/skipped/reindexed/errors，且与后台分类索引互斥。
- 页面回归：确认文本、按钮状态、进度计数和完成后刷新正确。
- 全量验证：现有 unittest、compileall、schema、architecture 和 `git diff --check` 门禁继续通过。
