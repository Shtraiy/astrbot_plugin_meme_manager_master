# 已整理表情缩略图卡片设计

日期：2026-08-02

## 背景

表情索引页的“已经整理好的表情”当前以纯文字卡片展示文件名、分类和描述。用户需要点击卡片后才能判断图片内容，浏览效率较低。

本次改动只针对索引页的已整理/待分类条目卡片，不改变普通管理页的分类表情网格。

## 目标

- 在每张索引卡片中优先展示表情缩略图。
- 保留文件名、分类和索引状态信息。
- 保留现有点击预览、懒加载、失败重试和待分类流程。
- 桌面端保持较高信息密度，窄屏自动降低列数。
- 不新增后端接口或改变 API 数据结构。

## 方案

在 `pages/semantic/script.js` 的 `renderCard()` 中创建缩略图元素，并继续使用当前 `meme_image_data` 接口加载 `preview` 尺寸图片。卡片整体仍是可点击按钮，点击后调用现有 `showPreview(item)`。

卡片结构：

```text
┌────────────────┐
│    缩略图      │
├────────────────┤
│ fool_0002.gif  │
│ fool · 已索引  │
└────────────────┘
```

缩略图使用固定比例容器，图片使用 `object-fit: cover` 或等效的稳定裁切策略。图片加载前显示占位态，加载失败显示错误态并保留原有重试行为。文件名单行省略，完整名称通过 `title` 与无障碍标签保留。

左侧已整理列表和右侧待分类列表复用同一张卡片结构；待分类/重复状态只通过状态文案与边框色区分。

## 视觉与响应式

- 桌面端使用自适应三到四列网格。
- 窄屏降为两列，保证缩略图和名称仍可辨认。
- 保留现有页面的圆角、浅色面板和绿色/蓝色状态体系。
- 悬停与键盘聚焦时增加轻微边框和阴影反馈。
- 遵守 `prefers-reduced-motion`，不新增必要性不足的动画。

## 安全与数据边界

- 图片地址只由现有预览 API 返回，不直接拼接本地绝对路径。
- 用户可见文本继续通过 `textContent` 写入，避免引入动态 HTML。
- 不修改后端路径校验、预览大小限制或索引数据结构。

## 测试与验收

补充前端静态回归测试，验证：

1. 索引卡片包含缩略图、文件名和状态文本。
2. 图片加载继续经过 `meme_image_data` 预览接口。
3. 点击预览和失败重试逻辑仍存在。
4. 样式包含响应式列数、固定缩略图区域和键盘焦点状态。

验证命令：

- `python -m unittest discover -s tests -v`
- `node --check pages/semantic/script.js`
- `node --check pages/a_manage/semantic/script.js`
- `git diff --check`

最终在桌面与窄屏浏览器中检查缩略图清晰度、名称可读性、加载失败状态和点击预览行为。
